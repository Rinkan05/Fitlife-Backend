Guía de Evaluación N.º 4: Arquitectura REST & Seguridad JWT
Autenticación Stateless (JWT)

A diferencia de las sesiones clásicas de Django que guardan el estado en la base de datos o memoria, el token JWT viaja en cada cabecera HTTP de forma stateless. Esto permite que el backend pueda escalar horizontalmente en múltiples instancias EC2 detrás de un balanceador o API Gateway sin compartir memoria de sesiones.

Ciclo de Vida de Tokens

El Access Token tiene una vida útil corta (2 horas) para reducir la ventana de riesgo si es interceptado. El Refresh Token (7 días) se almacena de forma segura y solo se envía a /api/token/refresh/ para renovar las credenciales sin obligar al usuario a reintroducir su contraseña.

Política de Permisos

Implementado con IsAuthenticatedOrReadOnly: las operaciones de lectura (GET) son públicas o de consulta segura, mientras que las mutaciones de datos (POST, PUT, PATCH, DELETE) son estrictamente validadas contra la firma criptográfica del JWT.
